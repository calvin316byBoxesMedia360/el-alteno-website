# El Alteño — Restaurant Website

Official website for **El Alteño — Auténtica Comida Mexicana**, Watsonville, CA.
Bilingual (EN/ES) site with the full digital menu, private-events booking, signature drinks and location.

> **Resuming this project?** Start with [`../HANDOFF.md`](../HANDOFF.md) — it is the current working document and supersedes `CONTEXT.md`. Read [`../DEPLOYMENT.md`](../DEPLOYMENT.md) before deploying.

## Quick Start

```bash
npm install                    # first time only
cp .env.example .env.local     # then fill in NEXT_PUBLIC_FORMSPREE_ID
npm run dev                    # prints Local and Wi-Fi URLs; binds to the LAN
```

```bash
npm run build
```

`npm run build` must pass before any deploy.

## ⚠️ The menu is not editable free-form

`src/data/menu.ts` is generated by transcribing the **printed flyer**. The transcription lives in [`../MENU-SOURCE.md`](../MENU-SOURCE.md).

**Never add a dish, price or description that is not on the printed menu.** These are real prices a customer pays at the counter — a guessed number becomes an argument at the register. If the restaurant changes the menu:

1. Photograph the new printed menu
2. Update `MENU-SOURCE.md` first
3. Then update `src/data/menu.ts` to match

Items whose price is unconfirmed are kept in the file with `available: false` so they stay hidden from customers until verified. `src/data/menu.ts` has one such placeholder today (Mojarra Frita).

### Known gaps — confirm with the restaurant before publishing

| Gap | Why it's blank |
|---|---|
| Breakfast / brunch dishes | The flyer only says *"Pregunte Por Nuestros Desayunos"* |
| Drink prices (Cantarito, Sunrise, Chavela) | Not printed on any material — the site says "Ask your server" |
| Mojarra Frita price | Still served, but absent from the printed flyer |
| "Popular" badges | Removed — nobody has confirmed which dishes actually sell best |

## Tech Stack

Next.js 16 (App Router) · React 19 · TypeScript · Tailwind CSS v4 · shadcn/ui · Framer Motion

**Language and theme are React Contexts, not routing.** `next-intl` is installed but unused for routes — there are no `/en` or `/es` paths. Components call `t("English", "Español")` from `LanguageContext`.

## Design System — "Cálido Artesanal"

The client **rejected** a saturated red/orange palette. Keep it warm and restrained.

| | Light (soft beige) | Dark |
|---|---|---|
| Page background | `#D2C09C` | `#161311` |
| Card surface | `#E4D6B8` | `rgba(250,246,239,.05)` |
| Text | `#241E17` | `#FAF6EF` |
| Muted text | `#554B3F` | `#A39485` |
| Accent (`--accent`) | `#85340F` terracota | `#C99A3F` mustard |
| Primary (buttons) | `#C65D3B` | `#C65D3B` |

**Two rules that are not obvious.** Measure the *card*, not the page: on a phone the dish cards cover almost the whole screen, so the card is what sets perceived brightness. And any surface that is dark in **both** themes — the footer, the dish modal — must not read `--muted-foreground` or `--accent`, because those hold dark ink meant for beige; those surfaces take the dark values literally.

Brand mustard reads 2.0:1 on beige and brand terracota 2.3:1, so **neither works as text in light mode**. Use `text-accent`, which resolves per theme. `globals.css` carries the full reasoning.

Fonts: **Playfair Display** (headings) + **Lato** (body), via `next/font/google`.
